### `prompt` — chat 시스템 프롬프트 조립

조립 순서:
1. **헤더** — "You are TARS..." + Current time + Response Formatting (코드 박힘) [→ ID-002]

- `defaultStaticBudgetTokens = 7000` (bootstrap sections 합)

좋은 패턴. CLAUDE.md "every tool description inflates prompt" 비용 의식과 정렬.

→ 사용자(콘솔) + LLM(빌트인 툴) 모두 4 파일 편집 가능.

## ID-001 (KB 효용) 정밀화

이번 세션의 핵심 부산물 — KB가 chat prompt path에 **전혀 통합 안 됨**:

| 메모리 종류 | prompt path 통합 |
|------------|-----------------|
| semantic entries (compaction + experience + explicit) | ✅ collectSemanticMatches |
| Experience JSONL | ✅ collectExperienceMatches (fallback) |
| MEMORY.md | ✅ collectMemoryFileMatches (fallback) |
| daily logs | ✅ collectDailyLogMatches (fallback) |
| sessions transcripts | ✅ collectSessionMatches (fallback) |
| **KnowledgeNote (KB wiki)** | ❌ **없음** |

→ KB는 (1) `memory_search` 의 `include_knowledge=true` 명시 시에만 read, (2) Prior Context 섹션에는 fallback 매처 없음. **chat 시 자동으로 KB 활용 0%**.

ID-001의 가설 A ("write side는 존재, read side 미완성")가 더 강하게 입증됨. 가설 B (확장 베이스) 측면에서 보면 chat path 통합은 의도적 future work일 수도. 사용자 결정 시 이 데이터 포함.

### 분리의 정당성 (검토 결과 OK)

- `prompt.BuildOptions.ForceRelevantMemory` flag로 받는 구조 — caller(`tarsserver/helpers_chat.go`)가 force 결정. prompt는 정책-agnostic. **정당**.
- `memoryCache`가 `tarsserver` 에 — prompt는 cache 모름. caller-책임 패턴. **정당**.
- `sysprompt` ↔ `prompt` 분리 — sysprompt는 edit path (HTTP+빌트인툴), prompt는 build path. 책임 다름. **정당**. 다만 **메타 분산은 별개 문제 [RF-024]**.
