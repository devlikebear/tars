## 좋은 패턴 (이미 잘 된 것)

### 1. RegistryScope 강제 prefix 가드 — CLAUDE.md 약속의 정확한 구현

```go
var registryForbiddenPrefixes = map[RegistryScope][]string{
    RegistryScopeUser:       {"pulse_", "reflection_", "ops_"},
    RegistryScopePulse:      {"ops_", "reflection_"},
    RegistryScopeReflection: {"ops_", "pulse_"},
}

func (r *Registry) Register(t Tool) {
    for _, p := range registryForbiddenPrefixes[r.scope] {
        if strings.HasPrefix(t.Name, p) {
            panic(...)
        }
    }
    ...
}
```

CLAUDE.md *"scope-forbidden prefixes panic at Register time — programmer errors, not runtime conditions"* 정확히. 빌트인 → user surface 누수가 wiring 시점에 차단. **모범 패턴**, 다른 영역에 적용 검토 가치.

### 2. CanonicalToolName 단일 진입점

40+ alias가 `tool_name.go` 한 곳에 모임. 외부 호출자가 친숙한 이름으로 호출해도 dispatch:
- `shell_execute`/`shell_exec`/`run_command`/`terminal_exec`/`execute_shell` → `exec`
- `read`/`write`/`edit` → `read_file`/`write_file`/`edit_file`
- `memory_save`/`memory_search`/`memory_get` → `memory` (aggregator)
- `memory_kb_*` → `knowledge` (aggregator)

→ user-facing alias는 **풍부**, 실제 등록 이름은 **canonical만**. 좋은 분리.

### 3. Group + Policy 4-rule resolution

Policy block reasons:
- `group_deny` — 그룹 자체 deny
- `tool_deny` — 개별 deny
- `group_allow` — allow-list에 그룹 없음
- `tool_allow` — allow-list에 개별 없음

`BlockedToolError` 가 rule + tool + group + source 모두 보관 → 디버깅 쉬움. CLAUDE.md *"add prioritized allowlist to project .claude/settings.json"* (fewer-permission-prompts) 같은 패턴이 정확히 이 인프라.

### 4. resolvePositiveBoundedInt 헬퍼

read_file/memory_search/glob/list_dir/web_fetch 5곳에서 사용. default + max + override → 정규화 일관성. 사용자 요청 새 관점("필요한가/유용한가") 적용 → **명백히 유용**, 5 caller가 검증.

### 5. validateNaturalTaskPrompt — 좁은 caller, 명확한 가치

`automation_cron.go` 두 곳 (cron job 등록/수정 시 prompt 검증)에서만 사용. **좁고 명확**. cron 등록 시 prompt에 sh injection 토큰(sudo/rm/curl/wget/&&/;) 박힘 방지. 실용적.

## 새 발견 (RF급)

### RF-026 — Registry.Register silent overwrite

scope 가드는 panic으로 강제되지만 **같은 이름 중복 등록은 silent overwrite**. 첫 등록이 흔적 없이 사라짐. 시나리오:

- 빌트인 + 외부 플러그인이 같은 이름 등록
- alias가 canonical 이름과 충돌
- 같은 helpers_agent.go 에서 두 번 register (실수)

→ scope 가드와 같은 정책으로 panic 또는 logger.Warn. wiring 시점 에러.

### RF-027 — `IsExecToolName` 이중 정규화

```go
return canonical == CanonicalToolName("shell_exec")  // 사실상 canonical == "exec"
```

alias map이 single source인데 `CanonicalToolName("shell_exec")` 를 매번 호출. 이중 정규화 비용 + 의도 불명. 1줄로 단순화 가능.

### RF-028 — `dispatchAction` ↔ `normalizeAutomationActionInput` DRY 위반

`aggregator.go:9-11` 코멘트가 자백:
> `dispatchAction` ... is the generic version of normalizeAutomationActionInput without cron-specific id aliasing.

차이는 6줄 (`id` → `job_id` 별칭). 본문 거의 동일. base + 후처리로 단순화.
