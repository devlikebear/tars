### 3단계 — 시맨틱

**`semantic.go` (708줄)**: 시맨틱 검색 코어. 4 레이어 (Config + 타입 + Service 메서드 + 헬퍼).

**핵심 디자인 — 통합 `MemoryEntry`**:

`Kind` 필드로 3종 구분 (`explicit_memory`, `compaction_summary`, `compaction_memory`). 단일 JSONL 인덱스(`memory/index/entries.jsonl`)에 다 저장. **하나의 query로 여러 메모리 종류 검색** — 단순한 통합 모델.

**`Search` (L313-399) — 하이브리드 scoring**:

```
score = cosineSimilarity(query_emb, entry_emb)
      + lexicalBoost(entry, terms)              // term당 0.06, all-match +0.05
      + (sessionID 일치 ? 0.12 : 0)             // 같은 세션 컨텍스트 우선
      + recencyBoost(entry.UpdatedAt)           // 48h:0.05 / 7d:0.03 / 30d:0.015
      + importance / 200                        // 0.005~0.05
```

**좋은 디자인**: semantic만 쓰면 키워드 hit 못 잡고, lexical만 쓰면 paraphrase 못 잡음 → 하이브리드.

**ContentHash 기반 dedup**:

같은 hash면 score 높은 것만 유지. ContentHash 없으면 Abstract로 fallback.

**Model migration 안전장치**:

```go
if entry.EmbeddingModel != s.config.EmbedModel ||
   entry.EmbeddingDimensions != s.config.EmbedDimensions {
    continue
}
```

→ embedding 모델 변경 시 옛 entries는 자동 무시.

## 핵심 인사이트

### 좋은 패턴

- **통합 `MemoryEntry`** — Kind로 분기, 한 인덱스에 다종 저장
- **하이브리드 scoring** — semantic + lexical + session + recency + importance
- **Model migration 안전장치** — 모델/dimension 일치 체크
- **컴파일 타임 인터페이스 검증** (`var _ Backend = ...`)
- **bootstrap 파일 default template** — 사용자 안내
- **atomic file write** (tmp + rename)
- **`cosineSimilarity` divide-by-zero 가드**
- **단계적 recency boost** (step function, exponential 아님)

### 흥미로운 비대칭

- write side (`derivation.go`): "prefer/선호" → category 트리거
- read side (`normalizeSemanticTerms`): "prefer"는 stopword (의미 X), "선호"는 stopword 아님 (의미 O)

→ write 쪽이 더 적극적, read 쪽이 더 conservative. 의도는 명시 X → RF-018에 정렬.

### 확장성 한계

`upsertEmbeddedEntry` 의 O(N) load+rewrite는 Phase 1 minimum 한계. 사용량 증가 시 RF-017 진행.
