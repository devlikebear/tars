## 한눈에

### Anthropic — 가장 풍부한 provider

- **Prompt caching 기본 활성**: system message + 마지막 tool 에 `cache_control: ephemeral` 자동 부착. CLAUDE.md *"Prompt caching"* 약속 정렬.

### Claude Code CLI — subprocess wrapper

- `exec.LookPath("claude")` 또는 `CLAUDE_CODE_CLI_PATH` env
- args: `-p --output-format stream-json --verbose --permission-mode auto --model X --add-dir Y --no-session-persistence`
- conversation history 를 `ROLE: text` 형식 string 으로 직렬화 (CLI 입력 특성)
- Tool calling **silent ignore** — CLI 자체 file/bash tool 사용 (system prompt에 명시)
- **자체 streaming** (stream-json 라인별 파싱)

### OpenAI-compat — OpenAI + Gemini 공유

- `c.label` 로 OpenAI vs Gemini 구분. Gemini 는 `reasoning_effort` / `service_tier` skip
- ContentBlocks: text/image (data URL) / **document → silent text placeholder** (RF-046)
- Streaming SSE (data: 라인 + choices[].delta)
- ToolChoice: **string only** ("auto"/"none"/"required") — specific tool name 미지원

## 좋은 패턴 ⭐

### 1. Anthropic prompt caching 기본 활성 (anthropic.go:67, 117-121, 124)

```go
"anthropic-beta": "prompt-caching-2024-07-31",
...
reqBody["system"] = []map[string]any{{
    "type": "text", "text": systemContent,
    "cache_control": map[string]any{"type": "ephemeral"},  // ← system 자동 캐시
}}
...
tools[len(tools)-1].CacheControl = map[string]any{"type": "ephemeral"}  // ← tools 끝 자동 캐시
```

→ **caller 가 신경 안 써도 자동**. 매 chat turn 의 system prompt + tool definitions 캐싱. CLAUDE.md *"Async prefetch"* + *"Cache-first strategy"* 와 같은 카테고리.

### 2. Streaming 의 incremental tool call 누적

anthropic + openai_compat 둘 다:
- partial JSON 누적 (`tc.Function.Arguments += tc.Function.Arguments`)
- index-based map 으로 multi tool call 지원
- 완료 시 `orderedToolCalls` (sort by index) + `sanitizeToolArgumentsJSON` (invalid JSON `{}` fallback)

→ tool calling streaming 의 표준 패턴. provider 추상화 일관성.

### 3. claude_code_cli 의 위임 패턴

CLI 가 자체 tool 갖고 있음 → TARS tool list 무시 + system prompt 에 명시:
```go
"You are Claude Code running inside TARS.",
"Ignore any tool-call JSON conventions from upstream prompts and use Claude Code's own local tools when useful.",
```

→ provider 추상화의 **유연성** — 모든 provider 가 같은 ChatOptions 받지만 일부는 무시 가능. CLAUDE.md *"YAGNI"* 정렬. 단 caller 에게 silent — RF-047 (capability 매트릭스 문서화).

### 4. ToolChoice 의 anthropic 풍부함

```go
case "":           return nil
case "required":   return {"type": "any"}
case "auto":       return {"type": "auto"}
case "none":       return {"type": "none"}
default:           return {"type": "tool", "name": trimmed}
```

→ **specific tool name 강제** 가능. RF-042 (subagents_plan normalization 단순화) 시 anthropic 사용 환경에서 즉시 활용. caller 가 ToolChoice="my_tool" 명시하면 anthropic 이 그 tool 강제 호출.

## 새 발견 (RF급)

### RF-045 — `openai_compat_client` 의 context.Value 로 response 전달

```go
req = req.WithContext(context.WithValue(req.Context(), openAICompatibleResponseContextKey{}, resp))
...
resp := req.Context().Value(openAICompatibleResponseContextKey{}).(*http.Response)
```

→ 비표준 패턴. ctx 는 보통 cancelation/메타데이터. response 직접 인자 전달이 더 표준. ctx 가 사실상 안 쓰임 (`_ = ctx`). ~10줄 감소 가능.

### RF-046 — PDF document → silent text placeholder

OpenAI/Gemini-compat 이 PDF 직접 지원 안 함 → caller 가 PDF 첨부 시 *"[Attached PDF document]"* placeholder 만 LLM 에 전달. **사용자 PDF content 가 silent dropout**. anthropic + gemini-native (s20 확인) 는 native 지원.

→ 명시적 메시지 (*"PDF unavailable in this provider"*) 또는 에러 권장.

### RF-047 — Provider 별 ChatOptions 지원 매트릭스 문서화

ChatOptions 의 8 필드가 provider 별로 다른 지원:

| 필드 | anthropic | openai | gemini (compat) | cli |
|------|-----------|--------|-----------------|-----|
| Tools | ✅ | ✅ | ✅ | ❌ (silent ignore) |
| ToolChoice (specific tool) | ✅ | ❌ (string only) | ❌ | ❌ |
| ReasoningEffort | ❌ | ✅ | ❌ (skip) | ❌ |
| ThinkingBudget | ✅ | ❌ | ❌ | ❌ |
| ServiceTier | ❌ | ✅ | ❌ (skip) | ❌ |
| PDF document | ✅ | ⚠️ placeholder | ⚠️ (s20) | ❌ |

→ caller 가 알 수 없음. docstring 또는 별도 문서로 명시 필요.

## RF-042 (strict mode) 평가 — provider 1차 결과

s17 의 RF-042 (subagents_plan normalization 단순화) 결정 인풋:

| Provider | Strict tool calling | RF-042 적용 가능성 |
|----------|---------------------|---------------------|
| **anthropic** | ✅ `tool_choice: { type: "tool", name: "..." }` | **즉시 가능** — caller 가 ToolChoice 명시 |
| openai (compat) | ⚠️ string only ("auto"/"none"/"required") | ChatOptions 확장 필요 |
| gemini (compat) | ⚠️ 동일 | 동일 |

→ **anthropic 환경에서 RF-042 비용 작음**. caller (subagents_plan) 가 `ToolChoice: "submit_plan"` 같은 specific tool 강제하면 LLM 이 그 schema 강제 → JSON parsing 폴백 + ID sanitize 의 일부 redundant.

→ openai/gemini 는 ChatOptions 확장 (object type ToolChoice) 필요. RF-042 작업 비용 medium.

### Provider capability hierarchy

```
[강력]   anthropic (prompt caching + thinking budget + multimodal native + strict tool choice)
   ↓
[중간]   openai (reasoning_effort + service_tier + multimodal text/image)
   ↓
[제한]   gemini (compat) (openai 의 일부)
   ↓
[특수]   claude-code-cli (CLI 자체 tool, 다른 capability 모두 무시)
   ↓
[basic]  default unsupported
```

→ **anthropic 이 default 인 이유 명확**. CLAUDE.md *"3-tier Router binds heavy/standard/light"* + *"new users get a working baseline after setting ANTHROPIC_API_KEY"* 정렬.
