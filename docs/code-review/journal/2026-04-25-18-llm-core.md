## 패키지 한눈에

### 핵심 추상화 3 layer

```
[Layer 1] Tier  (heavy / standard / light)
                       ↓ Tiers map (config-driven)
[Layer 2] Role  (chat_main, gateway_planner, pulse_decider, ...)
                       ↓ Role → Tier mapping
[Layer 3] Router  (config-driven dispatch)
                       ↓
       Client (Ask + Chat) → 5 providers
```

Router 의 의도된 사용 패턴 (docstring):
> "Construct exactly one Router at server startup with three pre-wrapped tier clients; hand it to every subsystem (chat, pulse, reflection, gateway, compaction); callers ask for a client by Role and remain oblivious to which tier or model actually served them."

→ **매우 명시적**. config-only role-tier reassignment 약속. 8 caller 가 Role 만 알고 tier/model 무관 → architectural clarity.

### Client interface 단순함

```go
type Client interface {
    Ask(ctx, prompt) (string, error)
    Chat(ctx, messages, opts ChatOptions) (ChatResponse, error)
}
```

→ **YAGNI 정렬**. Streaming/Tools/Reasoning 은 ChatOptions 로 처리. 다형성 폭발 없이 5 provider 지원.

### 2. TierResolution 의 source 필드

### 3. Selection metadata merge 패턴

`mergeSelectionMetadata` (selection_context.go:45-78) — override empty 만 적용:

```go

if override.Tier != "" { out.Tier = override.Tier }

```

→ **상위 메타가 하위 호출에서 보존**. role/tier/provider/model 은 router 가 셋, sessionID/runID/agentName 은 상위 호출자가 셋, flowID/stepID 는 가장 하위 (subagents_orchestrate) 가 셋. 자연스러운 hierarchy.

### 4. Fallback client 의 신중한 분류

```go
func shouldFallback(err error) bool {
    if err == nil { return false }
    if errors.Is(err, context.Canceled) || errors.Is(err, context.DeadlineExceeded) {
        return false  // 사용자 cancel/timeout 은 fallback 안 함
    }
    var perr *ProviderError
    if errors.As(err, &perr) { return true }
    return false  // 알 수 없는 에러는 fallback 안 함
}
```

→ **conservative**. 모호한 에러로 fallback 하지 않음. CLAUDE.md *"Don't add error handling, fallbacks ... for scenarios that can't happen"* 정신. (단 production wiring 없음 — RF-044)

### 5. Provider abstraction 단순함 + 5 provider 지원

`Client` 가 2 메서드 만으로 OpenAI/Anthropic/Gemini-native/Claude-Code-CLI/OpenAI-Codex 모두 지원. Streaming 은 ChatOptions.OnDelta 로 처리. **응집도 ↑ 추상화 비용 ↓**.

### 6. ProviderError + Unwrap

```go
type ProviderError struct {
    Provider, Operation string
    StatusCode int
    Message string
    Cause error
}
func (e *ProviderError) Unwrap() error { return e.Cause }
```

→ `errors.As` 가능. fallback_client 의 `errors.As(err, &perr)` 분류에 사용. 표준 Go error 패턴 정렬.

## RF-042 (s17, strict mode) 결정 인풋

`Client` interface 에 strict tool calling / structured output 지원 메서드 없음. ChatOptions 에:
- `Tools []ToolSchema` — 있음
- `ToolChoice string` — 있음 ("auto", "none", "required")
- `ReasoningEffort` / `ThinkingBudget` / `ServiceTier` — 있음

→ **strict tool calling 의 provider-specific 옵션** 은 추상화 안 됨:
- Anthropic: `tool_choice: { type: "tool", name: "..." }` — 강제 호출
- OpenAI: `response_format: { type: "json_schema", strict: true }` — strict 검증
- Gemini: structured output via `responseSchema`

→ RF-042 진행 시 ChatOptions 확장 또는 provider-별 helper 필요. **RF-042 의 작업 비용 큼**.

s19/s20 에서 각 provider 의 strict 지원 검토 후 결정 권장.
